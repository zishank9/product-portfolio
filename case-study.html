Improving a SaaS customer onboarding workflow

An example of how I would turn a customer problem into a scoped feature, actionable requirements and a testable release.

← Back to portfolio

1. The problem

Imagine a SaaS platform where new customers struggle to complete onboarding because required setup steps and their current status are not clear.

2. The objective

Help customers understand the remaining setup steps and make onboarding progress easier to track.

3. Proposed solution

  • Display a checklist of required onboarding tasks.
  • Show each task's status: Not started, In progress or Complete.
  • Explain what action is needed for incomplete tasks.
  • Provide a clear confirmation when setup is complete.

4. Example user story

User story

As a new customer, I want to see my onboarding tasks and their completion status so that I know what I need to do before I can start using the platform.

5. Acceptance criteria

AC1 — Display tasks

Given a customer has signed in, when they open onboarding, then all applicable setup tasks are displayed.

AC2 — Update status

Given a setup task has been completed, when the system confirms completion, then the displayed status updates accordingly.

AC3 — Handle errors

Given a task cannot be completed because of a system error, when the error occurs, then the customer receives a clear message and guidance on what to do next.

6. Prioritization

  • Must have: Task list and accurate task statuses.
  • Should have: Helpful instructions for incomplete tasks.
  • Could have: Optional progress visualization.
  • Later: Personalized onboarding recommendations.

7. Validation and release plan

  • Review requirements with relevant stakeholders.
  • Walk through edge cases with engineering.
  • Prepare UAT scenarios for task completion and error handling.
  • Validate the feature in a test environment.
  • Coordinate release readiness and monitor reported issues after launch.

8. How success could be measured

  • Onboarding completion rate.
  • Time taken to complete onboarding.
  • Number of onboarding-related support requests.

These are proposed metrics, not measured results. A baseline and target would be established using actual product data.

9. My approach

I would focus on clarifying the customer problem, agreeing on scope, writing testable requirements, aligning stakeholders, coordinating delivery and validating the result against the intended outcome.
