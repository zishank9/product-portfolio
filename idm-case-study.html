Case Study 03 · Identity & Integrations

Delivering Enterprise Identity Integrations and Migration Solutions

How I translated enterprise identity requirements into actionable delivery plans, coordinated engineering work for client integrations, and implemented an AWS Lambda function for a planned identity migration initiative.

Role

Product Delivery Manager

Primary focus

Identity integrations and delivery coordination

Technologies

Amazon Cognito, AWS Lambda, databases

Key responsibilities

Requirements, user stories, testing, go-live readiness

Project Overview

Enterprise clients required identity management integrations to support authentication and user access within a hospitality platform. This involved understanding client-specific requirements, coordinating implementation with developers, and ensuring integration work was prepared for delivery.

Separately, an identity migration initiative required a solution to support moving user identities between existing database-backed identity records and Amazon Cognito, as well as between Cognito environments.

These related areas of work required a combination of product delivery, technical coordination, requirements analysis, and hands-on implementation for the Lambda component.

The Challenge

  • Translate enterprise identity and authentication requirements into clear implementation tasks.
  • Coordinate work across product, development, and testing so that integrations were ready for client use.
  • Address client-specific business requirements within the identity migration solution.
  • Develop a migration component that could support a larger planned identity migration without overstating the scale of migration actually completed.

Workstream 1: Enterprise IDM Integration Delivery

My role and contributions

  • Worked with enterprise clients to understand identity integration requirements and business expectations.
  • Translated requirements into user stories and actionable delivery tasks for developers.
  • Coordinated with the development team on integration setup within the product environment.
  • Helped clarify requirements and investigate issues during implementation and testing.
  • Supported delivery readiness and coordination ahead of client go-live.
Delivery principle: Identity integrations must satisfy business requirements while being tested and coordinated carefully before production use.

Workstream 2: Identity Migration Solution

Understanding the requirement

A separate initiative aimed to support migration of user identities from existing database-backed records to Amazon Cognito, as well as migration between Cognito environments. The broader initiative was intended to support a large user population.

My contribution

  • Worked through the client-specific business requirements for the identity migration behaviour.
  • Implemented an AWS Lambda function to support the required migration functionality.
  • Worked on the solution for database-to-Cognito and Cognito-to-Cognito identity migration scenarios.
  • Used my understanding of the requirements and technical troubleshooting to connect the intended business behaviour with the implementation.

Delivery status and scope

The Lambda function was implemented during my tenure. However, the planned large-scale migration was not executed before I left the company.

Important distinction: The migration component was implemented, but the intended large-scale user migration should not be described as completed. This case study distinguishes delivered implementation work from the broader migration plan.

My Delivery Approach

  1. Understand: Clarify business requirements, integration expectations, and client-specific needs.
  2. Translate: Convert requirements into user stories and clear implementation expectations.
  3. Coordinate: Work with developers and testing teams to address questions and delivery dependencies.
  4. Implement and validate: Contribute to the Lambda migration component and support integration testing and issue investigation.
  5. Prepare for delivery: Support integration readiness while keeping the status of implementation and planned migration activities clear.

Outcomes and Contributions

  • Translated enterprise identity requirements into structured user stories and development tasks.
  • Supported engineering coordination for IDM integrations intended for enterprise client use.
  • Implemented an AWS Lambda function for the planned identity migration initiative.
  • Worked across business requirements and technical implementation to address identity migration needs.

The planned large-scale migration itself was not completed during my tenure, so no claim is made that the target user population was migrated.

Key Learnings

  • Identity integrations require clear requirements and coordination across technical teams.
  • User stories should make expected business behaviour understandable to developers and testers.
  • Technical implementation and production rollout are separate delivery milestones and should be reported accurately.
  • Product delivery often requires enough technical understanding to clarify requirements, investigate issues, and help teams reach a shared solution.
